# Nodes Manager implementation plan

## Objective and ownership

Implement a usable Nodes Manager inside ControlPanel based on the locally checked-out ComfyUI Manager frontend contracts. The primary agent owns this plan, source/API investigation, validation, and review. Only `gpt-6-luna` subagents at `max` reasoning effort edit implementation code, styles, dependencies, and tests, including fixes requested during review. `implement_nodes_manager` owns backend/routes/constants, client/controller, and their tests. `implement_nodes_manager_ui` owns React components/pages/CSS, ControlPanel integration, UI tests, and user-facing docs. The primary coordinates contracts between them and makes no implementation edits.

Preserve the pre-existing React migration and all unrelated dirty changes. Do not commit, deploy, restart ComfyUI, or perform real install/update/disable/delete operations as part of verification.

## First-release scope

- Add a Nodes Manager entry to the existing ControlPanel and a large responsive React dialog with sidebar filters and cards inspired by the provided screenshot.
- Support All Extensions, Not Installed, All Installed, Updates Available, and Disabled. Search by pack name, ID, author, and description; sort by name and available catalog metadata. Include installed Git/unregistered packs even when absent from Registry catalog.
- Display available pack metadata, installed version, latest version, enabled state, source, and operation result. Use safe image URLs, lazy loading, fixed image dimensions, and a fallback when metadata/images are missing.
- Provide Registry version selection and exact-version installation. Resolve the default choice from the catalog's actual version, keeping both `version` and `selected_version` identical; never silently replace a user's exact choice with `latest` or `nightly`.
- Support install, update, enable, disable, and uninstall through Manager v2 APIs. Offer version switching for installed Registry packs through the same explicit install contract. Confirm uninstall and replacement/version-switch operations using the existing ComfyUI dialog facility. Respect Manager permission/status errors.
- Keep the catalog local: prefer ControlPanel SQLite Registry data, then the established legacy JSON fallback. If neither is available, read the existing Manager Registry JSON cache as a final read-only fallback, with an explicit source/warning. Do not require changing repository-data override settings merely to browse already cached Manager data. Add read-only local API routes, including a version-list route that fetches Registry data on demand for the selected pack. Do not fetch versions for every card.
- Bound DOM work with paginated cards (48 per page) and CSS content visibility. This deliberately uses native pagination rather than introducing a virtualization dependency. Filters/sort reset pagination; counts and page controls must be clear.
- Expose loading, empty, missing-cache, unavailable-Manager, failure, unknown-result, and restart-required states. Refresh reads after confirmed terminal work.
- Persistent update locks, conflict detection, workflow/missing-node mapping, Algolia search, and bulk mutation are outside this first release. Do not render pretend working navigation for these features.

## Verified inputs and contracts

Local reference: `V:/workspace/Python/ComfyUI_frontend/src/workbench/extensions/manager/`.

- `services/comfyManagerService.ts`: base path `/v2/`; installed read `GET /v2/customnode/installed`; enqueue `POST /v2/manager/queue/task`; start `POST /v2/manager/queue/start`; status `GET /v2/manager/queue/status`; history `GET /v2/manager/queue/history` (filter by task `ui_id` and client).
- `types/generatedManagerTypes.ts`: queue body is `{ kind, params, ui_id, client_id }`. Install requires `{ id, version, selected_version, mode, channel }`, with optional repository. Follow `composables/nodePack/usePackInstall.ts` for `mode: cache`, `channel: dev`, and exact version field pairing. Update uses `{ node_name, node_ver? }`; enable uses `{ cnr_id }`; disable/uninstall use `{ node_name, is_unknown }`. Do not mix parameter models.
- Installed response is a map keyed by folder name with `ver`, optional `cnr_id`, optional `aux_id`, and `enabled`. Folder keys are not necessarily Manager operation IDs: use the canonical CNR ID for registered pack mutations, and inspect core's unknown-pack ID resolution for unknown Git mutations. Keep folder keys only as location identities; disabled keys may contain `@version`. Reconcile repository/aux identity for Git matching and prefer an enabled copy over a disabled duplicate. Disabled still means installed. Git CNR checkout `ver` may be a commit hash but its update `node_ver` is `nightly`; unknown Git update uses `unknown`, as required by `unified_update`.
- History's generated type is `{ history?: Record<string, TaskHistoryItem> }`, but installed Manager 4.2.2 also returns `{ history: TaskHistoryItem }` for a single `ui_id` query. Normalize both shapes, or use client-filtered map reads and match exact task. An item has `ui_id`, `client_id`, `result`, and optional `status: { status_str: success|error|skip, completed, messages }`. Never infer success from an empty queue or enqueue HTTP success. Match this client's task; absent/unrecognized result stays pending/unknown, with retry/manual refresh. The enable worker reports success without checking `unified_enable`'s result: refresh installed data and surface discrepancies before claiming the requested state was applied.
- The browser already has `app.api.fetchApi`; reuse this transport and actual `clientId`/`initialClientId`. Keep requests relative to ComfyUI. Manager can return empty bodies and structured `message` errors.
- Existing backend cache helpers: `registry_cache_path`, `controlpanel_manager_cache_source_dir`, `read_manager_repository_data_channel`, `is_allow_flagged_version_as_latest_enabled`, and `registry_cache.read_registry_cache`. Preserve SQLite, source status, and established Active/Flagged projection behavior. The global catalog does not contain full version histories for every node.
- Version list: official Registry `/nodes/{id}/versions` or `/versions?nodeId=...`, as confirmed by current official specification/source. Validate ID, bound pagination, preserve version status/reason, and expose failures without changing the selected version. A Flagged selection must be clearly labeled and remains subject to Manager policy; no security-setting override.
- Official references checked on 2026-10-04: https://docs.comfy.org/custom-nodes/js/javascript_overview ; https://github.com/Comfy-Org/ComfyUI-Manager/blob/main/glob/cnr_utils.py ; https://github.com/Comfy-Org/ComfyUI-Manager/blob/main/glob/manager_server.py . The guessed `docs.comfy.org/manager/new-manager` URL was unavailable; use concrete local v2 generated types plus official Registry sources. Source verification does not prove a live installed Manager API.
- Installed source checked at `V:/ComfyUI/portable_260711/.venv/Lib/site-packages/comfyui_manager/`: Manager 4.2.2. Read-only localhost:8188 probes confirmed ComfyUI 0.37.0, 49 installed packs, idle queue status, and an empty client-filtered history. New ControlPanel code is not deployed by this task; these probes verify existing Manager reads only.

Derive this final fallback path through `manager_user_dir`, `manager_url_cache_filename`, and the existing Registry nodes URL rather than hardcoding the hash. ## Completion criteria and stop rules

- The existing ControlPanel remains functional; Nodes Manager opens/closes/reopens from it and never leaves an active poll behind after close.
- Exact-version install request and all mutation payloads match verified v2 contracts; no successful installation is claimed without terminal evidence.
- Local catalog filtering is independent of original Manager UI/Algolia; read failures remain visible and retryable.
- Install/update/version-switch outcomes refresh installed reads and show restart requirements without automatically restarting.
- Required validation and build pass, or a concrete environmental/pre-existing blocker is documented with exact evidence. Implementation-caused failures must be fixed.
- No live installation or other real mutation is needed for acceptance here. If a running ComfyUI is available, read-only endpoint/browser checks may be performed and reported separately. Otherwise mark actual Manager queue execution and visual runtime unverified.
- Do not expand into workflow/conflict reconstruction, persistent pins, a generic queue framework, or unrelated migration fixes. Record any genuine API mismatch rather than silently changing payloads.
