## Nodes Manager

`Local folder` lists ordinary directories from all configured custom-node roots and their `.disabled` directories, excluding Git checkouts, Registry `.tracking` installations, hidden folders, and `__pycache__`. These entries retain their full-path identities and are read-only. Check same-named folders in different roots, disabled entries, search, and category counts without executing Manager mutations.

In `.main > .toolbar`, `Git nodes` exposes `Fetch all` and `Updates Available` exposes `Update All`. Each action processes the entire category regardless of the search query, through the existing per-pack update execution and result tracking. Targets run sequentially; duplicate batches and card mutations are disabled while a batch runs. Closing the dialog stops further submissions, and an uncertain task outcome stops the batch. Validate with mocked jobs/queue histories; live updates require a separate runtime check.

Restart ComfyUI after updating ControlPanel so the local catalog and Registry-version routes are registered. Open ControlPanel → Nodes Manager and check the catalog source label, search, the catalog filters and two Workflow filters, name/star/update sorting, and continuous scrolling through the first, middle, and final results without Previous/Next controls. Resize the Nodes Manager viewport across column breakpoints and confirm the responsive cards still scroll to the final result. Search, filter, and sort changes should return to the top after search commits; ordinary version or task-status updates should leave the scroll position in place. Tab to the Extensions region and use Page Up/Page Down and Home/End to confirm keyboard scrolling works. Check variable-height cards with loaded versions, Flagged reasons, and task results for clipped content or measurement jumps.

For the Workflow filters, open a representative workflow with a nested subgraph and confirm `Workflow custom nodes` lists each identified extension pack once across the root and nested graph. `Workflow missing nodes` should include only packs confirmed absent from Manager's installed list; disabled packs remain installed and retain their disabled state. Check that unknown, ambiguous, and unavailable runtime node types appear in the diagnostics area without becoming guessed install targets. A repository mapping without a Registry entry should be visible but read-only. Built-in `Note`, `MarkdownNote`, `Reroute`, and `PrimitiveNode` types should not be attributed to a custom pack, while a runtime custom node with a colliding type name should still resolve from its Python module. Opening and refreshing Nodes Manager must leave the workflow graph and saved node properties unchanged. Keep this check read-only; do not enqueue install, enable, disable, or uninstall operations.

Click “Choose a version…” to load Registry versions, verify the button shows “Loading versions…” while pending, and confirm the selector appears only after a successful response. On failure, verify the error and Retry button remain available. The backend requests only the first five Active versions and the first five Flagged/Pending versions combined, so the selector contains at most ten versions and excludes Banned versions. Check that Active versions have no suffix, Flagged/Pending versions use `(Flagged)`/`(Pending)`, and any Banned update version shown outside the selector uses `(BANNED)`. Installation requests must retain the original version string without the display suffix. Confirm a selected version and visible task status remain available after scrolling cards out of view and back. Check installed Git and Registry packs, including disabled packs and packs absent from the catalog.

When ComfyUI-Manager is unavailable, verify the installed-data error and that mutation buttons are disabled. For Manager task UI checks, use a test ComfyUI environment: inspect install, exact-version switch, update, enable, disable, uninstall confirmation, pending/failed/unknown/skipped results, accepted-task queue-start retry, and restart notices. Do not treat an accepted queue request as a completed node change; completion must be confirmed by Manager history and refreshed installed data. No real install or uninstall is required for routine automated validation.
